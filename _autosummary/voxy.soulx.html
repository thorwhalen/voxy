voxy.soulx¶

SoulX-Singer (Soul AI Lab, 2026; code and weights Apache-2.0): zero-shot singing voice synthesis and conversion, as the soulx singing backend.

>>> import voxy
>>> voxy.sing("melody.mid", "Light a can-dle in the win-dow", backend="soulx")

How it runs: in its own environment (python -m voxy setup soulx: Python 3.11, torch 2.2, transformers 4.41, the upstream pins). SoulX-Singer has no pyproject.toml, so pip can’t install it: voxy fetches its repository at a pinned commit (SOULX_SOURCE) into models/soulx/source/<commit> on first use, and the adapter puts that folder on sys.path. Weights (two 2.8 GB checkpoints, SVS and SVC, plus RMVPE for F0) come from the Hugging Face Hub at pinned revisions; SVC also loads openai/whisper-base (Apache-2.0) on first use. On Apple Silicon it runs on MPS, with the vocoder on the CPU; elsewhere on CUDA or the CPU (about 8x real time).

What it reads: SoulX metadata, a list of segments, one entry per note in every field, made here from voxy.score notes by soulx_metadata:

{“index”: “target_0”, “language”: “English”, “time”: [0, 6080],

“duration”: “0.30 0.60 …”, “text”: “<SP> Light a candle candle …”, “phoneme”: “”, “note_pitch”: “0 64 64 67 …”, “note_type”: “1 2 2 3 …”, “f0”: “”}

note_type is 1 for a rest (<SP>), 2 where a word starts, 3 where it continues; a word sung over several notes is written on each. Phonemes are left empty and filled in the worker (English, g2p_en), so the host needs no phonemizer. A synthesis prompt needs the same metadata, aligned to its clip (soulx_prompt_metadata).

Usage disclaimer (upstream README; not a licence term): do not use the model to impersonate anyone without authorisation or to create deceptive audio; respect intellectual property, privacy and personal consent.

>>> from voxy.score import Note
>>> meta = soulx_metadata([Note(0.0, 0.5, 64, "hel"), Note(0.5, 0.5, 67, "hel", False)])
>>> meta[0]["text"], meta[0]["note_type"], meta[0]["duration"]
('<SP> hel hel <SP>', '1 2 3 1', '0.30 0.50 0.50 0.40')

Module Attributes

DFLT_LEAD_S

Rest before the first note and after the last (upstream's examples start with <SP>).

DFLT_MIN_REST_S

A gap shorter than this joins the previous note (legato); a longer one is a rest.

DFLT_SPLIT_REST_S

A rest longer than this ends a segment.

DFLT_MAX_SEGMENT_S

No segment longer than this (upstream allows 60 s; shorter is safer on MPS).

SOULX_ENV

Upstream's inference pins (its requirements.txt minus the preprocessing, web UI and training stacks).

voxy.soulx.fit_voice_shift(target, prompt)[source]¶

Semitones that move target into the register of the voice singing prompt: median prompt pitch minus median target pitch, over notes.

Upstream computes this per segment (and weights notes by their phoneme count), so a long song would change key between segments; voxy computes it once.

>>> fit_voice_shift([Note(0, 1, 60), Note(1, 1, 64)], [Note(0, 1, 55)])
-5
Return type:

int

SoulX-Singer metadata (segments, phonemes left empty) for sung notes.

The line starts lead_s after a rest, gaps of min_rest_s or more become rests (shorter ones join the previous note), and a segment ends at a rest longer than split_rest_s or before it would pass max_segment_s.
