voxy.diagnosis¶

Diagnosis pages: render one text through a grid of (model x parameters), listen side by side.

>>> from voxy import diagnosis
>>> variants = diagnosis.expand_grid([
...     {"backend": "f5tts", "params": {"nfe_step": [16, 32], "cfg_strength": 2}},
...     {"backend": "chatterbox", "params": {"exaggeration": [0.3, 0.6]}},
... ])
>>> results = diagnosis.render_grid(text, references, variants, "out/")
>>> diagnosis.build_page(results, "out/", title="First listen")

Or from a spec file: python -m voxy diagnose spec.json --out DIR --publish.

Every variant has a stable ID (F5-7KQ2) computed from its backend, model options, parameters and reference clip, never from the text, so “use F5-7KQ2” means the same configuration on every page and every chapter. The page shows, per variant, the ID, an audio player, the parameters (those that differ from the model’s defaults in bold), generation time and real-time factor, and lets each listener rate it (1-5) and write a note. Ratings stay in the listener’s browser; “Copy my notes” turns them into a text block to paste into a message.

For a page shared with other listeners: notes_sink saves every rating and note as it is made (to an annoquest server, whose owner page then lists them per listener), appendix folds the variants of some references into a collapsed section, and imported adds clips rendered elsewhere (a cloud service).

voxy.diagnosis.annoquest_request(results, *, request_id, page_url, title, intro='', api_url='/api/annoquest', appendix=None, prompt='How much does this sound like the real voice, and how natural is it?')[source]¶

The annoquest request a notes_sink page reports to: one item per variant (a 1-5 rating and a note), so the owner page reads the saved notes per listener. Register it on the server with python -m annoquest_server put-request <file>.

>>> r = annoquest_request([{"id": "CB-AAAA", "backend": "chatterbox"}],
...     request_id="abcdefgh12", page_url="https://example.org/p/", title="T")
>>> [(i["id"], i["title"], i["response"]) for i in r["items"]]
[('CB-AAAA', 'Chatterbox', 'stars')]

voxy.diagnosis.build_page(results, out_dir, *, title='Voice diagnosis', text='', references=None, intro='', appendix=None, backend_notes=None, notes_sink=None, noindex=False)[source]¶

Write out_dir/index.html: one card per variant, grouped by backend.

Parameters:

  • references (Mapping[str, Mapping] | None) – name -> {"audio": relative path, "text": ..., "label"?, "processing"?, ...} shown so listeners can compare with the real voice.

  • appendix (Mapping[str, str] | None) – reference name -> a note: the variants made from those references (and the references themselves) go in a collapsed section at the end, under the note.

  • backend_notes (Mapping[str, str] | None) – backend -> a note shown under its section heading (default: the local backend’s notes and licence).

  • notes_sink (Mapping | None) – {"kind": "annoquest", "url": "/api/annoquest", "request": id} saves ratings, notes, the listener’s name and clip plays as they happen (the page says so). Without it they stay in the listener’s browser.

  • noindex (bool) – Ask search engines not to index the page (for a page shared by link).

Return type:

Path

voxy.diagnosis.expand_grid(grid, *, references=('',))[source]¶

Variants from grid rows: list values are swept (cartesian product), scalars fixed.

A row: {"backend": ..., "params": {...}, "init": {...}, "label": ...}. init values may be lists too (e.g. {"variant": ["original", "turbo"]}). Every variant is rendered once per reference name.

>>> vs = expand_grid([{"backend": "f5tts", "params": {"nfe_step": [16, 32], "speed": 1}}])
>>> [(v.backend, v.params) for v in vs]
[('f5tts', {'nfe_step': 16, 'speed': 1}), ('f5tts', {'nfe_step': 32, 'speed': 1})]

list[Variant]

voxy.diagnosis.render_grid(text, references, variants, out_dir, *, model_factory=None, audio_format='mp3', resume=True, log=<built-in function print>)[source]¶

Render every variant to out_dir/audio/<id>.<format>; return (and save) the results.

Models are built one backend configuration at a time and closed before the next, so only one model is in memory. With resume, variants already in results.json (without error) are not rendered again.

Parameters:

  • text (str) – What every variant says.

  • references (Mapping) – Reference name -> voice (a VoiceProfile or {"ref_audio", "ref_text"}).

  • variants (Iterable[Variant]) – From expand_grid (their reference names key references).

  • model_factory (Callable | None) – (backend, **init) -> SpeechModel (default create_speech_model).

  • audio_format (str) – ‘mp3’ (default, small) or ‘wav’.

Return type:

list[dict]

voxy.diagnosis.run_spec(spec, out_dir, *, log=<built-in function print>)[source]¶

Render a spec’s grid and build its page; return the page path.

Spec keys: title, text (or text_file), references or voice (+ n_references), grid (rows for expand_grid), optional intro, audio_format, imported (see import_results), appendix, backend_notes, noindex and notes_sink (see build_page). With an annoquest notes_sink and a page_url (where the page will be served), the request to register on that server is written next to the page.

Path

voxy.diagnosis.variant_labels(results)[source]¶

Readable names: the backend’s name, then the values of the settings that vary between that backend’s variants. A result’s own label wins.

>>> rs = [
...     {"id": "a", "backend": "chatterbox", "params": {"language": "fr", "exaggeration": 0.3}},
...     {"id": "b", "backend": "chatterbox", "params": {"language": "fr", "exaggeration": 0.5}},
...     {"id": "c", "backend": "voxcpm", "params": {"cfg_value": 2.0}},
...     {"id": "d", "backend": "elevenlabs", "label": "ElevenLabs v3"},
... ]
>>> variant_labels(rs)
{'a': 'Chatterbox 0.3', 'b': 'Chatterbox 0.5', 'c': 'VoxCPM2', 'd': 'ElevenLabs v3'}

dict[str, str]
