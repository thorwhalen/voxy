voxy.envs

voxy.envs¶

Isolated Python environments for backends whose dependencies clash with yours.

Local voice-cloning models each pin their own torch, transformers and numpy, so they can’t share one environment (or yours). A backend declares an EnvSpec; ensure_env builds it once with uv under the data root and returns its interpreter, which voxy.worker then runs the model in:

envs/{name}/ one virtual environment per backend models/hf/ model weights (HF_HOME of every worker) models/{name}/ a backend’s other weights (e.g. Coqui’s TTS_HOME)

Nothing here is downloaded at import time; building an environment is explicit (ensure_env, or python -m voxy setup <backend>).

>>> spec = EnvSpec("demo", ("numpy",))
>>> spec.digest() == EnvSpec("demo", ("numpy",)).digest()
True
>>> env_dir(spec, rootdir="/data").as_posix()
'/data/envs/demo'

class voxy.envs.EnvSpec(name, requirements, python='3.11', torch_backend='cpu', env_vars=dict())[source]¶

Bases: object

What a backend’s environment holds.

Parameters:

  • name (str) – Folder name under envs/ (usually the backend name).

  • requirements (tuple[str, ...]) – uv pip install arguments (packages, pins, extras).

  • python (str) – Python version for uv venv.

  • torch_backend (str | None) – uv’s --torch-backend (‘cpu’ keeps CUDA wheels out; None leaves the index alone).

  • env_vars (Mapping[str, str]) – Extra environment variables for the worker process (values may use {models}, the backend’s own weights folder).
